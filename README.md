# Практикум Л9: из ноутбука в `prime report`

**Стартовая ветка семинара С9.** В расчёте среднего платежа оставлена учебная ошибка. Две из трёх проверок в `tests/test_ticket.py` сначала падают. Порядок работы и контрольные примеры — на [странице С9](https://github.com/tikhomirovd/python-for-ba-hse-2026/blob/master/09-из-ноутбука-в-решение/семинар/README.md).

Учебный репозиторий лекции 9 курса «Программирование на Python для бизнес-аналитики» (ВШБ НИУ ВШЭ, БАЦРФ).

За пару мы превращаем разведочный ноутбук в маленькую систему, которую можно запустить одной командой
и поставить на расписание: модуль с расчётом, команда `prime report --date`, настройки в `.env`, журнал
и повторный прогон по дням без дублей. Ровно этот каркас нужен итоговому проекту.

Данные — небольшой снимок ПРАЙМ в папке [`data/`](data/). Ни сеть, ни учебный сервер не нужны.

## Как начать

Нужны Git и uv — те же, что на всём курсе.

```bash
git clone https://github.com/tikhomirovd/prime-l9-workshop.git
cd prime-l9-workshop
uv sync
git checkout step-0
```

Проверка, что всё встало:

```bash
uv run python -c "import pandas, prime; print('готово, pandas', pandas.__version__)"
```

## Шаги

У каждого шага есть тег: это готовое состояние репозитория после шага.

| Тег | Что появляется |
|---|---|
| `step-0` | разведочный ноутбук и снимок данных |
| `step-1` | расчёт переезжает из ноутбука в модуль `src/prime/` |
| `step-2` | команда `uv run prime report --date 2026-08-24` |
| `step-3` | настройки и секреты в `.env` |
| `step-4` | журнал в файл вместо `print` |
| `step-5` | `prime replay`: учебное время, сбой посреди дня и повтор без дублей |
| `step-6` | запуск по расписанию: cron, launchd, Планировщик заданий Windows |

**Отстали или что-то сломалось** — догоняем одной командой:

```bash
git checkout -f step-3
```

`-f` выбрасывает ваши правки и ставит репозиторий ровно в состояние шага. Это и нужно: вы не чините,
а догоняете. Git при этом напишет про `detached HEAD` — для практикума это нормально.
